# Talent Pool 면접 일정·회원 통합 (2026-10-16)

면접 일정 관리는 기존 Talent Pool 사이드바의 일반 메뉴로 표시한다. 클릭하면 우측 작업 영역에서 면접 기능을 로드하며 기존 Interview 메뉴와 다른 기능은 유지한다. 직접 `/interview-management`에 접근하면 통합 화면으로 이동한다.

## 회원과 인증

- `app_members`를 회원·등급·상태의 기준으로 사용한다. 별도 면접 회원 관리와 비밀번호 변경 화면은 통합 모드에서 제공하지 않는다.
- 기존 회원은 기존 이메일과 비밀번호로 로그인한다. 서버에서 기존 해시를 검증한 첫 로그인에 Supabase Auth 계정을 연결하고 레거시 해시를 제거한다. 기존 Auth 계정과 이메일이 겹치면 두 계정의 비밀번호가 일치할 때만 자동 연결하며, 비밀번호가 다르면 기존 관리자 메뉴에서 초기화한다.
- 별도로 발급한 면접 계정은 Auth UUID와 면접 외래키를 유지한 채 기존 회원 목록에 포함한다. 계정을 삭제해도 면접 이력의 사용자 UUID는 보존하고 접근을 차단한다.
- 관리자/부문·사업부 채용담당자는 면접 채용담당자, 현업 담당자는 면접관, 지원자는 지원자로 기본 연결한다. 관리자는 회원 목록의 면접 권한에서 HRBP 등 별도 권한을 지정할 수 있다. HRBP의 부서 접근 범위는 면접 기능의 부서 설정에서 지정한다.
- 신규 계정의 초기 비밀번호는 기존 회원 생성 양식에서 담당자가 직접 입력한다. 관리자는 초기화 대화상자에서 새 비밀번호를 지정하며, 본인은 기존 내 정보에서 변경한다.
- 로그인은 관리형 Auth 세션으로 유지하며 새로고침 시 서버가 회원 활성 상태를 재검증한다. 비밀번호·해시는 회원 응답이나 브라우저 저장소에 저장하지 않는다.

## 적용과 접근 통제

`20261016090000_talenthub_unified_members.sql` 적용 후 서버와 런타임 설정에 `TALENT_AUTH_UNIFIED_ENABLED=true`를 활성화한다. 전용 Supabase 설정은 기존 `INTERVIEW_MGMT_SUPABASE_*`를 사용한다. `talent-auth.js`와 `/api/talent-auth/*`를 포함해 한 번에 배포한다.

브라우저의 회원 테이블 직접 읽기·쓰기를 제거하고 서버 전용 RPC로 회원 변경을 처리한다. DB에서도 호출자 상태와 권한을 다시 확인한다. 면접 역할은 기준 회원 상태와 매 요청 대조하며, 예전 면접 계정 관리 RPC는 차단한다. 기존 회원 데이터와 면접 예약은 삭제하지 않는다.

운영 배포는 현재 배포 소스를 SHA1으로 확인하고 관련 파일만 수정해 다른 기능의 미반영 변경을 보존한다. `scripts/prepare-talent-members-release.js <현재 배포 ID>`와 변경 목록을 사용한다. 회원 테이블 보호를 해제하지 않는다. 장애 시에는 통합 인증 경로를 유지한 수정 배포를 진행하며, DB 권한 변경 없이 구버전 화면만 되돌리면 기존 로그인은 동작하지 않는다.
